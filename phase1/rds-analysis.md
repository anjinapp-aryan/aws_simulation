# `modules/rds/` — Deep Trace (full `main.tf` read this phase)

- **Engine**: hardcoded `"mysql"` — this module is MySQL-specific, not generic RDS/Aurora (correcting any earlier implication it was engine-agnostic; the workshop repo's Aurora usage is a different module entirely, not this one).
- **Subnet placement**: `aws_db_subnet_group.this`, `subnet_ids = var.db_subnet_ids` — dedicated DB subnet tier (the third of the 3-tier subnetting seen in `modules/network`), never the app or public tier.
- **Security groups**: `vpc_security_group_ids = [var.rds_sg_id]` — a single SG, sourced from `modules/security_groups`' `aws_security_group.rds` (verified restricted to exactly one ingress rule from the backend service SG, in `security-groups-analysis.md`).
- **Encryption**: `storage_encrypted = true` (hardcoded, not optional), `kms_key_id = var.kms_key_id` — encryption at rest is not a toggle in this module, it's mandatory.
- **Multi-AZ**: `multi_az = var.multi_az` — real, configurable, this IS the nonprod/prod differentiator (`false`/`true` respectively, verified in the tfvars diff).
- **Instance class**: `instance_class = var.instance_class` — `db.t4g.micro` (nonprod) vs `db.t4g.small` (prod), verified.
- **Credentials**: two modes via `manage_master_user_password` (bool) — if `true`, Terraform sets `password = null` and lets AWS Secrets Manager auto-generate/rotate the master password (`master_user_secret_kms_key_id` used); if `false`, a caller-supplied `var.password` is used directly. The prod-realistic choice is the managed-password mode — avoids ever having a plaintext DB password in tfvars/state in the first place.
- **Lifecycle / deletion protection**: `deletion_protection = var.deletion_protection` (a real variable, not hardcoded) and `skip_final_snapshot = var.skip_final_snapshot` — when `skip_final_snapshot=false`, `final_snapshot_identifier` is set via `coalesce(var.final_snapshot_identifier, "${identifier}-final")`, guaranteeing a snapshot name always exists so `terraform destroy` can't silently skip the final backup by accident (a real safety default worth noting for the cost-safety checklist — a stray final snapshot is itself a small persistent cost after "destroy").
- **No `lifecycle {}` block found** in this file — correcting an earlier assumption that RDS had `prevent_destroy`; verified absent. `deletion_protection` (an RDS-API-level flag) is the actual safety mechanism here, not a Terraform-level `lifecycle` meta-argument.
- **Enhanced monitoring**: conditional IAM role (`count = var.monitoring_interval_seconds > 0 ? 1 : 0`) — only created if monitoring is actually enabled, avoiding an unused IAM role otherwise.
- **Backups**: `backup_retention_period`, `backup_window`, `maintenance_window` all variables — no hardcoded defaults visible in `main.tf` (would need `variables.tf` for actual defaults, not checked this phase).
- **Dependency relationship**: this module has zero internal cross-references to network/security_groups — it receives `db_subnet_ids` and `rds_sg_id` purely as inputs, meaning the actual VPC/SG wiring happens one level up, in `internal/app_data` (which calls both `modules/rds` and presumably threads through outputs from `internal/networking`) — confirms the dependency-injection style seen throughout this repo: leaf modules don't reach across to other leaf modules directly, composition modules (`internal/*`) do the wiring.

## Why database infrastructure needs more lifecycle protection than stateless infrastructure
An ECS task or ALB can be destroyed and recreated with zero data loss — they're stateless, Terraform can freely replace them. An RDS instance holds the only copy of your data; an accidental `terraform destroy` or a forced replacement (e.g. changing `identifier` or engine) means real, potentially unrecoverable data loss. `deletion_protection` + mandatory final snapshot are exactly the two Terraform-configurable guardrails against that — verified present and correctly wired to variables (not hardcoded true/false) so a learner can safely experiment with them in CHEAP_MODE with protection off, then understand why prod would flip both on.
